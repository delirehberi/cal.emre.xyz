# Security Policy

## Supported Versions

We release security updates and bug fixes for the latest version of **cal.emre.xyz**.

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

The security and privacy of our users and their cryptographic Nostr keys is a top priority.

If you believe you have found a security vulnerability in **cal.emre.xyz**, please do **NOT** report it through a public GitHub issue.

Instead, please send an encrypted or direct email to:
**`z@emre.xyz`**

### What to Include in Your Report
To help us triage and resolve the issue quickly, please provide:
1. **Description**: A clear overview of the potential vulnerability.
2. **Steps to Reproduce**: Detailed reproduction steps, sample event payloads, or a proof of concept (PoC).
3. **Impact**: An assessment of what an attacker could achieve (e.g., unauthorized access, key leakage, denial of service).
4. **Environment**: Browser version, operating system, and relay environment used during discovery.

---

## Response Timeline & Disclosure

- **Acknowledgment**: You will receive an initial response acknowledging your report within **48 hours**.
- **Assessment & Triage**: We will investigate and assess the vulnerability within **5 business days**.
- **Fix & Patch**: A fix will be developed, tested against our automated test suite, and deployed to production.
- **Public Disclosure**: Once resolved, we will coordinate public disclosure and credit the reporter in the release notes if desired.
